# Glossari tècnic - Pràctica d'Entorns de Desenvolupament

## Àmbit 1: Git/GitHub

### Branch
- **Anglès:** branch
- **Definició:** Línia de desenvolupament independent dins d'un repositori que permet treballar en noves funcionalitats sense alterar el codi principal.
- **Exemple:** vam crear una branch anomenada `feature-login` per desenvolupar el formulari d'accés.

### Clon
- **Anglès:** clone
- **Definició:** Còpia local completa d'un repositori remot que es descarrega al nostre ordinador per poder editar-lo.
- **Exemple:** vam fer un clone del repositori `pallets-flask` per començar a programar en local.

### Commit
- **Anglès:** commit
- **Definició:** Registre o instantània que guarda els canvis realitzats als fitxers del projecte amb un missatge descriptiu.
- **Exemple:** vam fer un commit amb el missatge "afegida la configuració inicial de Flask".

### Fork
- **Anglès:** fork
- **Definició:** Còpia d'un repositori aliè que es crea al nostre compte de GitHub i sobre la qual sí que tenim permisos d'escriptura.
- **Exemple:** vam fer un fork de `pallets/flask` per poder-hi pujar canvis.

### Merge
- **Anglès:** merge
- **Definició:** Acció d'integrar els canvis d'una branca dins d'una altra (generalment la principal o `main`).
- **Exemple:** vam fer un merge de la branca de tasques un cop comprovat que tot funcionava correctament.

### Origin
- **Anglès:** origin
- **Definició:** Nom predeterminat que rep el repositori remot d'on vam clonar el projecte original.
- **Exemple:** vam enviar els canvis al repositori remot utilitzant `git push origin main`.

### Push
- **Anglès:** push
- **Definició:** Comandament per pujar els commits locals de la nostra màquina cap al repositori remot a GitHub.
- **Exemple:** vam fer un push per sincronitzar els nostres fitxers locals amb GitHub.

## Àmbit 2: Metodologia àgil

### Backlog
- **Anglès:** backlog
- **Definició:** Llista prioritzada de totes les tasques, requeriments i funcionalitats pendents de realitzar en un projecte.
- **Exemple:** vam col·locar la tasca de documentació al backlog general del projecte.

### Iteració (Sprint)
- **Anglès:** iteration / sprint
- **Definició:** Període de temps curt i fix (habitualment de 2 a 4 setmanes) durant el qual l'equip desenvolupa un conjunt concret de tasques.
- **Exemple:** la Iteration 1 va durar tres setmanes, del 14 d'octubre al 3 de novembre.[cite: 13]

### Sprint Backlog
- **Anglès:** sprint backlog
- **Definició:** Conjunt de tasques del backlog general seleccionades específicament per ser executades durant el sprint actual.
- **Exemple:** vam moure la TASCA 1 i la TASCA 2 al sprint backlog per començar a treballar-hi.[cite: 13]

### User Story
- **Anglès:** user story
- **Definició:** Descripció breu d'una funcionalitat explicada des del punt de vista de l'usuari final del sistema.
- **Exemple:** vam redactar una user story per definir com volíem que s'afegissin els comentaris.

## Àmbit 3: GitHub Projects

### Assignees
- **Anglès:** assignees
- **Definició:** Camp o columna que indica quins membres de l'equip estan encarregats de resoldre una tasca o issue específica.
- **Exemple:** vam comprovar a la vista de taula que la columna assignees mostrava qui portava cada tasca.[cite: 16]

### Issue
- **Anglès:** issue
- **Definició:** Unitat de seguiment individualitzada a GitHub que s'utilitza per registrar tasques, errors o millores a implementar.
- **Exemple:** vam crear tres issues diferents per organitzar les tasques de la pràctica.

### Status
- **Anglès:** status
- **Definició:** Estat actual en què es troba una tasca dins del flux de treball del tauler (com ara Backlog, In Progress o Done).
- **Exemple:** vam canviar l'status de la tasca de Backlog a Sprint Backlog.

### View
- **Anglès:** view
- **Definició:** Diferents maneres de visualitzar i filtrar les dades d'un projecte (com ara tauler Kanban o taula).
- **Exemple:** vam crear una vista tipus board i una altra tipus table per complir amb la pràctica.[cite: 16]
